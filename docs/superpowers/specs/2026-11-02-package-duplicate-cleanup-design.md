# 零部件模板包重复与旧版本清理设计

## 背景与目标

零部件模板包和组件模板包保存在同一 MinIO bucket。零部件平台在发布前目前只按代码、版本和源修订检查冲突；组件平台会读取完整发布历史并只在目录投影中显示最新零件，但不会查找不同模板 ID 的内容重复包，也没有对象删除流程。

截至 2026-11-02，曾从 50 个发布包中人工清理 8 个包，剩 42 个；其中 5 个 Ω 立柱包具有相同的几何定义和参数定义，但发布 ID 不同。旧组件可能固定引用被清理的发布 ID。用户已明确选择不迁移这些引用；删除前告知受影响引用，确认后仍直接删除。

目标是在零部件平台与组件平台建立一致的重复识别契约。零部件平台在发布时先检查并提示；组件平台每次同步 MinIO 时独立重查并清理严格旧版本及完全重复包。内容高度相似但不是严格重复的包列为逐项确认候选。所有实际删除都会记录结果；不能访问 MinIO 或权限不足时明确失败。

## 决策

- 清理范围仅为 `templateKind=part` 的包；旧记录缺少 `templateKind` 时按零部件处理。组件发布包与其历史版本不由此机制删除。
- 过期版本是同一 `templateId` 下，按 `(version, createdAt, publicationId)` 排序后低于最新项的发布包。用户选择不设置 30 天保留期。
- 完全重复是包级 SHA-256 完全相同、但 publicationId 不同的零件包。每组保留创建时间最新者；同时间使用 publicationId 字典序选择唯一保留项。
- 高度相似使用版本化的内容规范化与评分规则。达到阈值的候选由用户逐项确认后删除；分数不等同于可自动删除。
- 被删除包的引用数量、来源及 publicationId 在确认界面展示，但不阻止删除。不会尝试把旧引用迁移至最新模板。已发布组件、草稿或其他成员可能无法再加载被删除包。
- MinIO 删除成功后立刻从发布目录消失。恢复包保存在平台本地数据目录，不写回 MinIO；审计数据不含密钥。恢复备份默认保留 30 天；到期后由存储检查页提供可审计的本地备份清理操作，不自动删除备份。
- 如果扫描无法读取或校验相关发布元数据、无法解析比较所需内容，受影响的自动候选不执行删除。明确选中的语义相似候选可在单项确认时再次核验对象哈希和路径；损坏或身份不匹配的对象仍只能列为异常，不能伪报为成功清理。

## 相似度标准 v1

两端共用同一组契约测试向量，分别实现规范化和评分，不共享 Python 模块。输入为完整 `.rwpart`，而不是发布名称、代码、发布时间、STL 文件名或总体积。

规范化先校验 ZIP 路径、文件数量和解压大小上限，再读取认可的 JSON 定义文件。键按 Unicode NFC 和稳定键序规范化；无语义顺序的实体集合按稳定内容排序，几何操作序列保持原序。包身份、发布 ID、作者、时间戳、证据记录、构建输出 URL 与输出哈希从相似性计算中排除。实体 ID 先在各自类型内按定义顺序编号，所有内部引用使用映射后的编号，保留拓扑和依赖关系。尺寸、单位、范围、默认值及表达式属于内容，不做容差舍入。

每组字段转为规范化的 `JSON Pointer=value` 集合，以 Jaccard 系数 `交集 / 并集` 计算相似度；空组得分为 0。类别与权重为：

| 类别 | 权重 | 比较文件 |
| --- | ---: | --- |
| 几何定义 G | 55% | 几何配方、草图约束、扫描路径、语义面 |
| 参数行为 P | 25% | 参数定义、参数依赖及表达式 |
| 特征与接口 F | 12% | 特征规则、变体、接口 |
| 制造与材料 M | 8% | 制造分类、材料要求与验证定义 |

总分 `S = 0.55G + 0.25P + 0.12F + 0.08M`，每个类别和总分均为 0–100：

- 相同包 SHA-256：完全重复，进入自动清理组。
- `S >= 90` 且 `G >= 95` 且 `P >= 90`：高度相似，必须逐项展示并经用户确认。
- `S >= 80`，或 `G >= 95` 且 `P >= 85`：疑似相似，仅作提示，不自动删除。
- 其他：不作为重复候选。

分数以两位小数呈现，并列出各类别分数、相同/不同的关键文件与字段。分数规则具有 `similarityVersion`；未知包结构、关键几何或参数文件缺失时记为 `unclassified`，不自动归并。

## 平台流程

### 零部件平台发布

新增发布预检：读取拟发布修订生成的 `.rwpart`，扫描 `read_prefix` 下全部零件发布，而不是当前按发布身份去重后的列表。结果分为同模板旧版本、完全重复、高度相似、疑似相似、检查异常，并显示 publicationId、名称、作者前缀、版本、评分、关键差异和已登记/本地引用数。

旧版本和完全重复包显示为本次发布后的自动清理项；高度相似包要求逐项勾选；疑似相似默认不选。用户确认发布后，先提交新的发布包与 metadata commit marker，再执行清理，避免新版本失败时先删除旧包。返回的发布结果分别报告 `published` 和每个 `cleanup` 状态；发布成功而删除失败时保留新包并明确报告旧包仍在 MinIO。不会以删除失败回滚已经提交的新发布。

### 组件平台同步

`LibrarySync` 读取完整零件历史后计算完全重复和同模板旧版本；组件和零件仍以 `templateKind` 分开处理。严格旧版本与完全重复项自动删除，语义相似候选在存储检查页展示并要求逐项确认。同步状态分别报告读取、分析和清理，删除失败不得将候选从缓存状态中错误标为已删除。

删除后重新读取 MinIO 元数据并验证目标对象确实消失，再应用最新目录快照。若 bucket 开启版本控制，需删除该对象所有版本和删除标记；若当前凭据没有对应权限，报告 `DELETE_PERMISSION_DENIED`，保留失败候选供重试。不会仅因目录隐藏或本机缓存更新而报告物理存储已清理。

### 清理审计与恢复

执行前将所选 `.rwpart` 与 `metadata.json` 复制到组件平台本地恢复目录，校验备份 SHA-256；备份未完成时不删除。备份默认保留 30 天，平台提供查看、恢复和手工清理入口；过期本身不触发自动删除。审计记录 bucket、key、publicationId、SHA-256、对象版本 ID、清理类别、相似度和差异、被影响引用、执行者、时间、MinIO 返回状态及备份路径。恢复使用原 key 和原始字节；如果原对象 key 已被新包占用则拒绝覆盖。

恢复目录与 MinIO 分离，不计入共享模板库容量。实现计划明确本地备份目录配置、UI 下载/恢复入口及审计记录访问权限；密钥绝不写进清理记录或浏览器。

## MinIO 权限与失败处理

当前线上账户对 `DeleteObject` 返回 `AccessDenied`。部署前须为平台使用的 MinIO 服务账户授予共享 bucket 下发布对象的 `s3:DeleteObject`；若版本控制启用，另需 `s3:DeleteObjectVersion`。限定到 `publishers/*/*/template.rwpart` 与 `publishers/*/*/metadata.json`，不授予 bucket 管理权限，也不允许清理 `reference-registry/`。检查和发布仍可在无删除权限时运行；清理报告失败且旧对象保留。

删除严格限定 metadata 中经验证的 `objectKey` 同级 `template.rwpart` 与 `metadata.json`，路径必须位于配置的共享发布前缀。每项删除前重新校验 SHA-256 和对象版本/ETag，避免删除扫描后已改变的对象。按 metadata commit marker 顺序处理，故障时记录已完成和未完成对象，不把部分成功报告为整批成功。

引用扫描继续读取所有已发布组件版本、嵌套组件、本地草稿/发布快照和 MinIO 共享登记。引用不作为删除闸门，这是用户明确选择；完整性失败仍阻断自动识别与批处理。由于客户端覆盖不是权威成员清单，界面必须把“引用影响统计”描述为已扫描范围，不能保证包含所有设备。

## 接口与界面边界

零部件平台新增只读发布预检响应与发布后清理明细，不公开 MinIO 凭据。组件平台扩展 `POST /api/template-library/cleanup-preview` 输出的候选类型、similarityVersion、分项评分、差异摘要、影响引用及删除权限状态；增加需显式选择 publicationId 与扫描摘要的清理操作。服务端必须重新检查候选与 key，不能接受浏览器提交任意对象路径。

“存储检查”显示包、候选类别、分数与差异、引用影响、可清理/检查不完整/权限不足/删除失败状态，并可筛选、导出审计与重试失败项。确认语明确说明旧引用不会迁移。完全重复与旧版本由组件平台同步服务自动清理；失败项可显式重试。高度相似项只有用户逐项勾选后，才通过清理接口删除；服务端根据 publicationId 和扫描摘要重新核验，绝不接受浏览器提交任意对象路径。

## 验收标准

- 两个平台在共享固定契约向量上得到相同类别、字段规范化结果和相似度分数。
- 改名、作者变化、发布时间、随机实体 ID、ZIP 压缩顺序和构建输出哈希变化不会改变语义分数。
- 任一几何操作、约束、参数默认值/范围/单位/依赖变化都会影响对应类别分数；权重门槛防止仅有相同名称或体积的包被判为高度相似。
- 零部件发布预检能识别不同 templateId 的完全重复/高度相似包；发布确认后先写新发布，再清理 strict candidates。
- 组件每次完整同步能发现漏过第一层的旧版本/重复包；旧组件固定引用会显示影响但按用户选择仍允许删除。
- 删除权限失败、网络异常、对象哈希变化、错误路径、部分删除、备份校验失败和开启版本控制的 bucket 都有可验证结果，不会显示成功或丢失重试记录。
- 仅零部件被此规则清理；组件包、引用登记文件、未选中的相似候选均保持不动。
- 删除后 API 不再列出目标包，指定对象按 bucket 版本策略确实不存在；恢复测试可按原 key 恢复原哈希。

## 非目标

- 不自动修改任何组件引用或替换其固定版本。
- 不删除组件发布历史、SQLite 草稿/快照、组件平台本机包缓存或 MinIO 引用登记。
- 不根据名称、编码、体积或预览截图直接删除包。
- 不配置全 bucket 生命周期清理规则。
- 不自动删除疑似相似 (`80–90`) 或 unclassified 对象。

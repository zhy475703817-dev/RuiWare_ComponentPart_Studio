# 组件工作台分层设计

用户已在本次对话批准“七阶段业务模块＋共享领域数据＋独立三维视图”方案并要求实施。

- `app` 组合布局、阶段导航和工作台状态；只使用 React 自带状态能力。
- `stages` 包含定义、装配、接口与槽位、参数、规则、验证、发布七个实际面板。
- `domain` 定义唯一组件草稿、纯 reducer、验证和 JSON 序列化，不依赖 React、DOM、网络和 Three.js。
- `library` 保留已实现的发布库读取、搜索、刷新、错误处理及点击详情展开/收起。
- `viewport` 独立管理三维场景与选择展示；本轮不下载包、不生成模型、不添加虚构装配成员。
- 组件引用使用 publicationId、templateId、version、sha256；连接及接口使用结构化成员/接口引用，允许标识含点号。
- 删除成员时清理连接、继承接口和参数绑定，清空对应槽位占用。编辑草稿增加 revision，界面切换不增加 revision。
- 页面状态与模型资源不写入导出。保留 component-1.0 的导出主体结构，扩展定义、参数定义、引用元数据、绑定和槽位信息。
- 分类及说明成为受控草稿字段；新建重置全部草稿和工作台选择。
- 基础数据验证与尚未实现的装配求解、规则执行分开标注；导出是草稿导出，不声称已发布。
- 工程单位 mm-kg-s，坐标系 right-handed-z-up；模型接入时在视图边界处理单位。

验收：已有发布库测试继续通过；领域层覆盖关联删除、不可变更新、固定版本引用、验证和导出；浏览器验证七阶段切换、受控字段保留、新建、详情折叠、搜索及真实发布库。模型预览、CAD、规则求值、正式发布服务不在本轮实现。

# 组件模板平台

## 代码架构

工作台已按七阶段拆分，草稿模型、数据操作、验证、导出、发布库及三维视图分别管理。入口仅负责启动；详细目录、依赖方向和后续模型接入位置见 [代码架构说明](docs/CODE-ARCHITECTURE.md)。

项目名称与项目编码、组件编码、负责人、所属组织、检索标签、组件内部和组件间连接形式、设计约束、证据附件，以及参数和规则统一保存到后端共享草稿。证据文件单个最大 5 MB、每份草稿最多 10 个且总计最大 15 MB；文件保存在本机草稿数据库中，导出的组件 JSON 会内嵌附件内容，可将该 JSON 一并提交到 GitHub，其他人下载后可导入并恢复文件。切换阶段和刷新页面不会丢失已保存内容。新建会创建独立草稿并重置工作台选择；右侧“共享草稿”可切换已有草稿或复制链接。草稿默认保存在 `.runtime/components.sqlite3`。

当前支持基础数据验证、草稿导出和组件结构版本发布。发布的组件会返回左侧列表，可作为一个成员加入其他组件并再次发布。装配求解、规则执行和组件整体三维显示仍待接入；发布结构版本不表示工程检查已通过。

## 组件发布与复用

1. 编辑组件名称；可从左侧模板的发布详情点击“加入当前组件”，加入零部件或已发布组件。
2. 切换到“发布”阶段，点击“发布组件版本”。平台等待本页修改保存后，创建固定版本；左侧列表自动刷新。
3. 点击“新建”，在左侧找到刚发布的组件，展开详情并点击“加入当前组件”，即可把它作为子组件使用；新组件也可再次发布。

当前先接通发布复用链路，允许中间阶段未完成、甚至尚无成员的结构版本进入组件列表；这些版本保留未通过及待接入检查提示，不因缺少模型而被零件模型检查过滤。零部件原有的模型可用性过滤保持不变。已发布组件目前显示版本信息和成员引用，尚不显示组件整体三维模型。

组件和零部件发布共用零部件平台现有 MinIO bucket 与 `RUIWARE_MINIO_*` 配置，不需要另建 bucket 或增加一套密钥。组件包也使用 `.rwpart`，通过发布元数据中的类型标记与零部件区分。MinIO 是共享发布库的来源；SQLite（默认 `.runtime/components.sqlite3`，可用 `COMPONENT_DRAFT_DB` 更改）继续保存草稿和待重试的不可变快照。上传失败时不会显示为已发布，草稿和快照会保留供重试。

同一草稿的同一修订重复发布返回同一版本；修改后发布生成递增版本。历史发布不会被草稿修改覆盖，子组件引用固定发布 ID、版本及 SHA-256，不会自动升级。只允许引用已存在且校验一致的组件发布版本，因此不会形成版本引用环。加入子组件只继承其公开接口及参数，不展开其内部成员；零部件目前加入固定引用与默认参数，对外接口提取留待接口阶段完善。

新增接口：`POST /api/component-drafts/{draftId}/publish`（请求包含 `expectedRevision`）、`GET /api/published-components`、`GET /api/published-components/{publicationId}`、`GET /api/published-components/{publicationId}/download`。组件包包含 `manifest.json`、`component.json` 和 `checks.json`；发布包先写入并回读校验，最后写入元数据使其出现在共享列表中。零部件原有发布接口保持原协议。旧的 SQLite 组件发布快照不会在启动时自动上传；如需迁移，可在项目根目录显式运行 `.venv\Scripts\python.exe -m backend.migrate_publications`，此操作保留原包字节、发布 ID 和哈希，并可重复执行。

## 启动

安装 Node.js 24+ 和 Python 3.12+ 后，双击 `start-component.bat`。首次启动自动创建本项目 `.venv`、安装 Python 和前端依赖，后台启动 FastAPI 与 Vite，检查就绪后打开 <http://127.0.0.1:5180>。服务日志位于 `.runtime`，重复启动会复用已运行的服务。如果本项目后端重载失败但仍占用端口，启动脚本会识别并重启该进程；无法确认归属的占用进程会保留，并提示其 PID。

前端运行在 5180，FastAPI 后端运行在 8020。配置共享 MinIO 后，无需启动零部件平台。Vite 仅将 `/api` 请求转发给 FastAPI，不承担业务接口或读取连接密钥。

后端接口文档：<http://127.0.0.1:8020/docs>，接口描述：<http://127.0.0.1:8020/openapi.json>，健康检查：<http://127.0.0.1:8020/api/health>。健康检查只表示组件后端运行，不代表上游发布库可用。

## MCP 接入

本平台同时提供 Streamable HTTP MCP 服务：`http://127.0.0.1:8020/mcp`，与 FastAPI 一起启动。工具覆盖发布库查询、版本详情、模型预览信息、共享草稿编辑、基础验证和 JSON 导出。网页与 AI 使用同一份草稿，空闲时自动同步 AI 修改并展示前后差异；并发编辑时同字段优先保留用户输入，其他字段保留 AI 修改。结构删除等无法直接合并的情况保留本页输入，可下载本地副本。具体连接配置、工具参数、访问令牌和同步行为见 [MCP 接入说明](docs/MCP.md)。

首次更新需安装新的 Python 依赖并重启后端；双击一键启动会自动检查依赖。默认仅允许本机 MCP 连接，远程部署可设置独立 `COMPONENT_MCP_TOKEN`，同时对网页和 REST 配置访问控制。

手动启动（在项目根目录，分别使用两个终端）：

```powershell
python -m venv .venv
.venv\Scripts\python.exe -m pip install -r backend/requirements.txt
.venv\Scripts\python.exe -m uvicorn backend.app.main:app --host 127.0.0.1 --port 8020 --reload --reload-dir backend
```

```powershell
npm ci
npm run dev
```

手动启动的服务可用 Ctrl+C 停止。一键启动的服务在后台运行；修改密钥配置后，先停止占用 8020 的本项目后端进程，再重新启动。修改 Python 代码会自动重载。

## 连接已发布零部件库

1. 确保服务器 MinIO 可访问，模板已上传至共享 bucket。
2. 组件平台沿用已有的 `RUIWARE_MINIO_ENDPOINT`、`RUIWARE_MINIO_ACCESS_KEY`、`RUIWARE_MINIO_SECRET_KEY`、`RUIWARE_MINIO_BUCKET`；读取目录由 `RUIWARE_MINIO_READ_PREFIX` 指定，默认 `publishers`。发布组件还需 `RUIWARE_MINIO_PREFIX=publishers/成员标识`。
3. 已有系统环境变量可直接使用，无需再配一套密钥；也可参考 `.env.example` 在本项目 `.env.local` 中填写。本项目不会自动读取另一个项目的 `.env` 或另一个终端临时设置的环境变量。
4. 重启组件平台的 FastAPI 后端。左侧读取零部件和组件共享发布库，可按名称/编码搜索、刷新和查看发布版本详情；已发布组件也可作为子组件加入。后端依次读取本项目根目录 `.env`、`.env.local`、系统环境变量，后者优先。

`.env`、`.env.local` 已被 Git 忽略。密钥仅供 Python 后端使用，不进入页面、浏览器请求或构建产物；不要将它命名为 `VITE_*` 变量。

组件后端直接扫描 MinIO 读取目录内的发布元数据，按 `templateKind` 区分零部件与组件；旧记录未标记类型时按零部件处理。没有最近 1000 条限制。零部件通过默认 3D 模型检查后才进入左侧列表，定义不足或几何无法生成的版本自动隐藏；组件结构版本保留既有发布复用规则。检查过程不对用户展示。

仅在未配置 MinIO 读取连接时，零部件读取回退到旧接口 `GET /api/public/v1/templates?limit=1000`，此模式需要启动零部件平台并配置 `RUIWARE_TEMPLATE_API_URL`、`RUIWARE_PUBLIC_API_KEY`。已配置 MinIO 后，连接失败会保留本地缓存并提示重试，不自动改用旧接口。

点击模板会读取并校验 `.rwpart`，在组件平台本地重建后显示模型，支持旋转、缩放、自动对焦和失败重试。发布包无需携带 STL。模板公开的用户输入参数可在画布中调整并更新模型；模型重建不会修改发布包、发布记录或当前草稿，也不会自动加入装配。收起发布详情不清除预览，新建会清除预览。

## 发布库加载与更新

首次打开会从共享发布库下载尚未缓存的包，零件通过默认模型检查后逐项显示，因此首次准备仍需等待。包、默认模型和检查结果保存在项目已有的 SQLite 数据库（默认 `.runtime/components.sqlite3`，沿用 `COMPONENT_DRAFT_DB`），不需要增加环境变量。以后重新打开页面或重启后端先读取本地列表及默认模型，后台直接检查 MinIO；已缓存的相同发布 ID 和包哈希无需重复下载或重建。零件和组件均直接从同一 bucket 读取，不依赖零部件平台进程。

页面打开期间约每五分钟在后台检查一次，启动后也会检查。发现新增、变更或移除时显示“发现 N 项模板更新”，点击“更新列表”后切换列表；顶部刷新按钮会立即检查并应用结果。本页发布组件成功后自动检查并更新列表。后台检查失败保留已有列表，单个包失败不阻塞其他健康包的首次展示；不完整检查不会把原有模板误删。

更新列表不改动当前编辑内容、已加入成员或其固定版本。网络断开时仍可查看缓存的零件默认模型及组件发布详情；组件发布和依赖校验仍需访问共享库。可调参数使用本机引擎重新生成模型，不会改写原包。引擎代码或相关依赖变化后重新检查模型，确认可用才显示；MinIO 地址、bucket 或读取目录变化后使用独立缓存，更换同一存储的密钥不清空缓存。损坏的包或模型缓存会在后续读取时自动重新获取或生成。

新增接口：`GET /api/template-library` 立即返回本地快照并按需启动后台检查；`POST /api/template-library/sync` 请求立即检查；`POST /api/template-library/apply` 应用已准备好的更新。旧发布库接口保留原有语义。缓存与草稿共用数据库文件，请勿通过删除整个数据库来清缓存，以免丢失草稿。历史包按发布 ID 和哈希分别保存，以支持已有版本引用，缓存会占用本机磁盘空间。

发布包应包含完整的几何定义、参数和材料验证信息；组件平台据此本地生成预览 STL。保留旧的包内/固定地址 STL 兼容预览接口，但画布重建不依赖 STL。CAD 引擎依赖会由一键启动脚本自动安装。完整契约和接口见 [模型预览接入说明](docs/PART-PREVIEW.md)。

## 常见提示

| 提示 | 处理方式 |
| --- | --- |
| 尚未配置连接密钥 | 填写本项目 `.env.local` 或设置系统环境变量后重启组件平台 |
| 零部件平台尚未启用接口 | 在零部件平台配置 `RUIWARE_PUBLIC_API_KEY` 并重启 |
| 连接密钥不正确 | 确认两个平台密钥一致，检查系统环境变量是否覆盖文件设置 |
| 连接密钥格式不正确 | 使用不含换行及控制字符的 ASCII 密钥，重启 FastAPI 后端 |
| 尚未配置共享发布库 | 检查组件平台可读取到的 MinIO 配置 |
| 无法连接 / 超时 | 检查 MinIO 地址、网络及共享存储服务；旧 HTTP 模式另需零部件平台运行 |
| 暂无模板 | 在零部件平台发布模板，确认同步成功后刷新 |
| 该发布版本没有可用的预览模型 | 检查包内几何定义、参数和材料信息，完善后发布新版本 |
| 模板包或模型校验失败 | 检查发布库对象和编译产物，不要覆盖历史版本 |

## 检查与部署

运行 `npm test` 检查前端领域数据、验证、导出和列表解析；运行 `.venv\Scripts\python.exe -m unittest discover -s backend/tests -v` 检查 FastAPI 接口、上游错误、配置和静态页面。运行 `npm run build` 检查并构建前端。`npm run preview` 同样转发 `/api`，需要后端运行。

本机运行构建版本：先执行 `npm run build`，再启动 `.venv\Scripts\python.exe -m uvicorn backend.app.main:app --host 127.0.0.1 --port 8020`（不带 `--reload`），打开 <http://127.0.0.1:8020>。FastAPI 同时提供 `dist` 页面、静态资源和 API，构建应在后端启动前完成。

若将 `dist` 单独部署到静态服务器，需把同源 `/api` 转发到 FastAPI；只复制前端文件不会包含后端。公网部署时通过正式反向代理提供 HTTPS，并按部署环境配置地址和访问控制。不要将密钥写入前端构建。
